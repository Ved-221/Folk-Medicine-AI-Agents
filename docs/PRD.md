## 1. Executive Summary & Vision

### 1.1 Problem Statement
Centuries of indigenous folk medicine and classical Ayurvedic therapeutic knowledge are largely undocumented in machine-readable formats. Much of this wisdom exists in oral traditions, aging practitioners' notebooks, or fragmented classical texts. Concurrently, modern generative Large Language Models (LLMs) pose severe clinical risks when queried on herbal medicine: they hallucinate dosages, invent unvetted remedies, disregard patient constitution (*prakriti* / *doshas*), and fail to identify critical contraindications or emergency red flags.

### 1.2 Product Vision
The **Folk Medicine AI Agents** system is an academic research platform and verifiable recommendation engine designed to preserve, structure, and safely retrieve traditional therapeutic knowledge. 

The core architectural maxim of this system is:
> **"Code governs decisions; LLMs only extract and rephrase grounded facts."**

The system guarantees that:
1. **Zero medical facts are generated by AI imagination**: Every recommendation maps deterministically to a verified source dataset row.
2. **Every extraction is provable**: All extracted context requires verbatim quote validation against the source text.
3. **Safety is deterministic and unbypassable**: Hard safety screening, emergency red-flag triage, and age-band dose adjustments execute in pure code *before* any generative model is called.

- **UC-4: Constitution-Aware Remedy Recommendation** — Retrieve the highest-ranking grounded remedy matching the user's dosha and symptoms, calculate age-adjusted dosage, and present an actionable 6-field summary.
- **UC-5: Clarification & Information Gate** — Withhold remedies when essential clinical variables (age or dosha) are missing, prompting the user for clarification.

## 3. Product Principles & Boundaries

### 3.1 What the Product IS
- An archival preservation engine for indigenous and classical Ayurvedic formulations.
- A deterministic hybrid retrieval system combining semantic embeddings, fuzzy string matching, and strict categorical dosha filters.
- A clinical safety boundary prioritizing patient safety and hospital escalation over remedy generation.

### 3.2 What the Product IS NOT
- **NOT a clinical diagnosis system**: Does not diagnose diseases or replace medical professionals.
- **NOT an autonomous agent**: No multi-agent emergent loops, no dynamic planning, and no unconstrained web browsing.
- **NOT an LLM decision-maker**: The LLM is strictly prohibited from selecting dosage, approving remedies, deciding safety, or altering contraindications.

## 5. Functional Requirements (FR)

### 5.1 Agent 1: Data Ingestion, Extraction & Retrieval

#### FR 1.1: Dataset Normalization & Scaffolding Trimmer
- **Input**: Raw JSONL records (`data/raw/ayurvedic_dataset.jsonl`).
- **Processing**:
  - Remove synthetic scaffolding (`dosage_model`, `treatment_plan`, `reasoning_steps`, `final_explanation`, `variation_simulations`).
  - Standardize dosha names to lowercase: `{"vata", "pitta", "kapha"}`. Normalize legacy references (e.g., `rakta` mapped to `pitta`).
- **Output**: Clean JSONL records stored in `data/clean/dataset.jsonl`.

#### FR 1.2: Context Extraction & Verbatim Quote Validation
- **Engine**: Gemini LLM via `src/common/llm_client.py` using prompt `extract_v1.txt`.
- **Fields Extracted**: `preparation_type`, `application_method`, `frequency`, `duration_days`, `season_restriction`, `time_of_day`, `carrier_substance`, `lifestyle_diet_cautions`.
- **Validation Invariants**:
  - Every extracted field must supply an exact, case-sensitive `supporting_quote` found in the source text.
  - If a quote cannot be verified verbatim as a substring of the source text, the extraction fails validation.
  - Caution flags in source text automatically mark the record as `needs_review` and route it to `data/review/review_queue.jsonl`.
  - Extracted caution flags may *add* caution but can *never* remove existing caution.

#### FR 1.3: Natural Language Query Parsing
- **Engine**: Hybrid LLM parser (`query_parse_v1.txt`) with deterministic regex fallback.
- **Capabilities**:
  - Extracts `symptoms` (str), `dosha` (normalized enum or None), `age` (int or None), `is_pregnant` (bool), `is_breastfeeding` (bool).
  - Handles vernacular and Hinglish idioms (e.g., *"chhati mein jalan"* -> acid reflux, *"sukhi khasi"* -> dry cough, *"pet kharab"* -> indigestion).
  - Deterministic Emergency Detector: Identifies life-threatening red flags (e.g., *"chest pain"*, *"coughing blood"*, *"shortness of breath"*) before any API call.

#### FR 1.4: Hybrid Retrieval Engine
- **Engine**: Tri-factor hybrid ranker (`src/agent1/query.py`).
- **Retrieval Pipeline**:
  1. **Dosha Hard Filter**: Excludes remedies contraindicated for the user's constitution; prioritizes tridoshic remedies and exact dosha matches.
  2. **Semantic Search**: Computes cosine similarity against pre-computed vector embeddings (`data/index/embeddings.npy`).
  3. **Fuzzy String Matching**: RapidFuzz token set ratio matching on condition names and symptom lists.
  4. **Combined Scoring**: `Score = (0.6 * Semantic_Score) + (0.4 * Fuzzy_Score)`.

### 5.2 Agent 2: Safety Verification, Dosage & Recommendation

#### FR 2.1: Deterministic Code Safety Gate
- **Engine**: Pure Python evaluator (`src/agent2/safety.py`).
- **Non-Bypassable Invariants**: Runs before any recommendation formatting; requires zero LLM tokens.
- **Triggers for Immediate Clinical Referral (`status: SEE_DOCTOR`)**:
  - `flags.is_emergency == True` or presence of critical red-flag symptoms.
  - `safe_for_home_remedy == False` in the matched dataset record.
  - `care_context` specifies emergency, specialist, or inpatient care.
  - Contraindication match (e.g., `is_pregnant == True` when record specifies pregnancy contraindication).
  - `review_status == "needs_review"`: Generates warnings and restricts dosage recommendations.

#### FR 2.2: Age-Banding Dosage Resolution
- **Engine**: Deterministic lookup table (`src/agent2/age_band.py`).
- **Age Brackets**:
  - **Infant (< 2 yrs)**: Excluded from home remedies. Mandatory clinician referral.
  - **Child (2–12 yrs)**: Pediatric adjustment (50% standard adult dose).
  - **Adolescent (13–17 yrs)**: 75% standard adult dose.
  - **Adult (18–64 yrs)**: Standard dose as documented in source text.
  - **Elderly (65+ yrs)**: Geriatric adjustment (50%–75% standard dose with monitoring precautions).
- **Dosage Provenance**: Every output explicitly states whether dosage was taken verbatim `from_source` or `derived` via deterministic age-banding.

#### FR 2.3: Constrained Recommendation Formatter
- **Engine**: LLM constrained formatter (`src/agent2/formatter.py`) with zero-shot temperature 0.0.
- **Fallback**: 100% deterministic template formatter used if LLM call fails, times out, or runs offline.
- **Output Schema**: Exactly 6 structured fields:
  1. `remedy`: Clean formulation name and route of administration.
  2. `dosage_by_age`: Exact dosage adjusted for patient's age band.
  3. `ingredients`: Specific herbs and preparation carrier substances.
  4. `lifestyle`: Associated lifestyle and dietary routines.
  5. `precautions`: Safety contraindications and monitoring checkpoints.
  6. `foods_to_avoid`: Clear negative dietary constraints.

## 6. Non-Functional Requirements (NFR)

### 6.1 Safety & Reliability
- **Zero Hallucination Tolerance**: 100% of medical and herbal entities in the output must exist in the retrieved dataset row.
- **Fault Tolerance**: The system must operate end-to-end without an active internet connection or Gemini API key using deterministic regex parsers and fallback formatters.
- **Deterministic Latency**: Safety gate and age-banding calculations must execute in under 10 milliseconds.

### 6.2 API Quota Optimization (Gemini Free Tier)
- **Call Guard**: Maximum 15 requests per minute, hard limit enforced by `src/common/llm_client.py`.
- **Persistent Disk Caching**: MD5 query-hashed response cache stored at `.cache/llm_cache.json`. Identical queries make zero network calls.
- **Selective LLM Use**: LLMs are never invoked for emergency queries, missing information queries, or safety rejections.

### 6.3 Code Quality & Testability
- **Plain Python Stack**: Strictly no complex agent frameworks (no LangChain, CrewAI, or AutoGen).
- **Type Annotations & Documentation**: Full PEP 484 type hints and docstrings on every function.
- **Test Coverage**: 100% test coverage on business logic with mocked LLM calls in unit tests. Full suite runs via `pytest`.

### 6.4 Data Security & Ethical Compliance
- **Zero PII Persistence**: User queries are processed in memory and not logged to disk.
- **API Key Protection**: API keys are loaded via environment variables and never printed, logged, or serialized.
- **Medical Disclaimer**: Every consultation output includes a clear academic research disclaimer noting that outputs are drawn from folklore archives and do not constitute clinical prescription.

## 7. Data Pipeline & Schema Definitions

### 7.1 Pipeline Stages
1. `data/raw/ayurvedic_dataset.jsonl`: Immutable ground raw records.
2. `data/clean/dataset.jsonl`: Synthetically stripped, normalized records.
3. `data/enriched/enriched_dataset.jsonl`: LLM-extracted context with supporting quotes.
4. `data/index/embeddings.npy`: Precomputed vector embeddings for fast retrieval.
5. `data/review/review_queue.jsonl`: Quarantine queue for records requiring human verification.
6. `data/gold/`: Curated benchmark queries and expected rows for precision/recall validation.
